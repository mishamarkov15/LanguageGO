# Домашнее задание 6

Модульные и интеграционные тесты для Ledger и Gateway из ДЗ 5. Код сервисов
не изменился, кроме функции `ledger.Reset()`: она очищает транзакции и бюджеты
в памяти, чтобы тесты не влияли друг на друга. Эндпоинты и примеры cURL — в
[README ДЗ 5](../hw-5/README.md). Запуск сервера из корня репозитория:

```sh
cd hw-6/gateway
go run .
```

Требуется Go 1.22 или новее. Для проверок используется
[testify](https://github.com/stretchr/testify) (`assert` и `require`), он
скачивается автоматически при первом запуске тестов.

## Что проверяется

`ledger/ledger_test.go` — unit-тесты домена:

- `TestTransactionValidate`, `TestBudgetValidate`, `TestCheckValid` — табличные
  тесты валидации: корректные данные, нулевые, отрицательные, `NaN` и бесконечные
  суммы и лимиты, пустая категория, неверная или несуществующая дата. Тесты не
  трогают общие данные, поэтому выполняются параллельно (`t.Parallel()`).
- `TestAddTransaction` — бюджеты: транзакция в пределах лимита и ровно до лимита
  проходит, превышение возвращает `ErrBudgetExceeded`, и количество транзакций
  в `ListTransactions()` не растёт. Также проверяются категории без бюджета,
  нумерация ID и 50 одновременных добавлений (проходят ровно 40 из 50).
- `TestSetBudget`, `TestListBudgets`, `TestListTransactions`, `TestLoadBudgets`,
  `TestReset` — создание и обновление бюджетов, сортировка, пустые списки,
  загрузка из JSON и очистка хранилища.

`gateway/internal/api/handlers_test.go` — интеграционные тесты через
`httptest.NewServer` на настоящем роутере:

- `TestBudgetsAPI` — `POST /api/budgets` возвращает `201` и бюджет,
  `GET /api/budgets` возвращает его в списке (или `[]`). Некорректный JSON,
  `limit <= 0` и пустая категория дают `400` и `{"error":"..."}`.
- `TestTransactionsAPI` — цепочка «бюджет → транзакция → список»: `201` и
  созданная транзакция, `200` и массив с ней. Превышение бюджета даёт `409` и
  `{"error":"budget exceeded"}`, некорректный JSON и данные — `400`.
- `TestRouting` — `404` для неизвестных путей и `405` с заголовком `Allow`.

В каждом ответе проверяется заголовок `Content-Type: application/json; charset=utf-8`.
Сценарии разбиты на подтесты `t.Run` (`ok`, `exceeded`, `bad_json` и т. д.).
Интеграционные тесты работают с общим состоянием ledger, поэтому не
параллельные: каждый подтест поднимает свой сервер и вызывает `ledger.Reset()`
в начале и в `t.Cleanup()`.

## Запуск тестов

`ledger` и `gateway` — отдельные Go-модули, поэтому тесты запускаются в каждом
из них. Из корня репозитория:

```sh
cd hw-6/ledger
go test ./... -cover -coverprofile=cover.out
go tool cover -html=cover.out -o cover.html
```

```sh
cd hw-6/gateway
go test ./... -cover -coverprofile=cover.out
go tool cover -html=cover.out -o cover.html
```

Подробный список подтестов выводится с флагом `-v`, проверка на гонки данных —
с флагом `-race`. Отчёт `cover.html` открывается в браузере и в git не попадает.
